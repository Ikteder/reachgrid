# ReachGrid 1.1 improvement specification

Date: 2026-09-07

Status: Approved for implementation

## Evidence-based need

ReachGrid 1.0 records one local reach session but cannot preserve evidence or compare two target sizes. Its README and catalog entry identify opt-in local history, paired per-cell comparison, and an explicit protocol for order effects and fatigue as the best next improvement.

## User outcome

A mobile developer can run a matched pair of target-size sessions on one device, see per-cell latency, miss, and score deltas, save completed evidence only after opting in, and export either the current result or the bounded local archive.

## Paired protocol

- The user chooses one of three fixed pairs: 24/32, 32/40, or 24/40 dp.
- Both phases use the same date seed, handedness, 4 by 6 grid, and 48-target route.
- A deterministic seed-derived assignment decides which radius runs first. This makes the order explicit and varies it reproducibly instead of always favoring the smaller or larger target.
- The app pauses between phases and asks the user to rest, reset their grip, and continue only when ready.
- Comparison is accepted only when both reports have the same seed and handedness and different radii.
- Every cell reports second-minus-first changes for median latency, misses, and reach score. Overall summaries are descriptive paired evidence, not a significance test or causal estimate.

## Local history

- Saving is off by default and controlled by an explicit checkbox.
- Completed individual sessions are stored in private app preferences only when saving is enabled.
- Each entry contains a save timestamp, an integrity digest, and the existing versioned session JSON.
- The archive is capped at 20 sessions, skips malformed stored entries, can be shared explicitly as versioned JSON, and can be cleared in the app.
- History does not add internet permission, accounts, telemetry, background work, or raw touch coordinates.

## Interface changes

- Add a run-mode selector for a single session or one of the three target-size pairs.
- During paired runs, show phase, assigned radius, and a rest transition.
- After the second phase, replace the single-session heatmap with a delta heatmap containing numeric score and latency changes.
- Add an opt-in save checkbox, saved-session count, share-history action, and clear-history action.

## Verification

- Extend the SDK-free Java harness for deterministic counterbalancing, compatibility validation, per-cell delta math, history bounding, malformed-entry tolerance, and privacy fields.
- Extend JUnit coverage for the same behavior.
- Run local Java compilation and the core harness.
- Run public Android unit tests, lint, and debug APK assembly.
- Confirm the manifest still has no internet permission and every README still contains no em dash character.

## Interpretation boundary

Counterbalancing reduces a systematic order choice but does not remove learning, fatigue, grip drift, or day-to-day variation. Two visits per cell in each phase remain a quick diagnostic. The app does not claim statistical significance, ergonomic certification, accessibility conformance, or population validity.
